# Командная строка #
{: id="Командная_строка" }

`gdb --args PROGRAM ARG1 ARG2 ... ARGN`

: Запустить отладочную сессию, передав отлаживаемой программе `PROGRAM` указанные аргументы `ARG1`, `ARG2`, ..., `ARGN`

`gdb {-p|--pid} $(pidof NAME)`

: • Найти идентификатор процесса по имени (`pidof NAME`);

  • Запустить отладчик и подключиться к процессу с найденным идентификаторм

  Для отладки путем подключения к запущенному процессу от обычного пользователя
  создать файл `/etc/sysctl.d/10-ptrace.conf` со следующим содержимым: `kernel.yama.ptrace_scope = 0`.

`gdb {-s|--symbols} FILE`

: Запустить отладчик и загрузить таблицу отладочных символов из указанного файла (`FILE`).

# Инструментарий #
{: id="Инструментарий" }

`attach PID`

: Подключить отладчик к процессу с указанным идентификатором (`PID`).

`bt | backtrace`

: Вывести стек вызовов.

`detach`

: Отключить отладчик от процесса, к которому он был ранее подключен.

`symbol-file FILE`

: Загрузить таблицу отладочных символов из указанного файла (`FILE`).

`file FILE`

: Установить отлаживаемую программу, указав её исполняемый файл (`FILE`).

`frame NUMBER`

: Выбрать указанный (`NUMBER`) стековый фрейм.

`info frame NUMBER`

: Вывести описание выбранного фрейма (`NUMBER`) на стеке.

  [Frame Info (Debugging with GDB)](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Frame-Info.html)

`! COMMAND | shell COMMAND`

: Выполнить указанную команду командной оболочки (`COMMAND`).

`b | break FILE:LINE`

: Установить точку оснанова на указанной строке (`LINE`) указанного файла (`FILE`) исходного кода.

`watch EXPRESSION`

: Установить точку наблюдения для заданного выражения (`EXPRESSION`).

  Отлаживаемая программа будет остановлена сразу же после изменения заданного
  выражения.

`list`

: Отобразить строки исходного кода до и после текущей исполняемой точки.

  Общий размер выведенных строк настраиваится командой `set listsize NUM`.

  Текущий размер списка выводится командой `show listsize`.

`list .`

: Отобразить строки исходного кода до и после текущей исполняемой точки.

`list LINE`

: Отобразить строки исходного кода до и после заданной строки `LINE`.

`list START,END`

: Отобразить строки исходного кода между начальной `START` и конечной `END` строками.

`info {b|breakpoints}`

: Вывести список заданных точек останова.

`delete BNUMBER`

: Удалить точку останова, заданную номером `BNUMBER`.

`run`

: Запустить отлаживаемую программу.

`[c]ontinue`

: Продолжить отладку программы после её останова на точке останова или по сигналу.

`next [N]`

: Продолжить выполнение отладочной программы после её останова со следующей строки
  и остановиться на данной строке.

  Не заходить в функцию если таковая имеется на текущей строке.

  Выполнять команду заданное количество раз (`N`).

`step [N]`

: Продолжить выполнение отладочной программы после её останова со следующей строки
  и остановиться на данной строке.

  Заходить в функцию если таковая имеется на текущей строке.

  Выполнять команду заданное количество раз (`N`).

`bt | backtrace [-full]`

: Вывести последовательность фреймов стека до данной точки вызова.

  Выводить значения локальных переменных (`-full`).

`info args`

: Вывести все аргументы и их значения на текущем фрейме стека.

`info locals`

: Вывести все локальные переменные и из значения на текущем фрейме стека.

`{p|print|inspect} EXPRESSION`

: Вывести значение заданного выражения (`EXPRESSION`).

`print -pretty -- *this`

: Вывести текущий объект.

`edit`

: Открыть текстовый редактор в текущей исполняемой точке.

  Текстовый редактор задается переменной окржения `EDITOR`.

`q | quit | exit`

: Завершить работу отладчика.

`tui enable` `<ctrl-x, a>`

: Активировать режим TUI.

`tui disable` `<ctrl-x, a>`

: Деактивировать режим TUI.

`focus src` `<ctrl-x, o>`

: Сфокусировать окно с исходным кодом.

`focus cmd` `<ctrl-x, o>`

: Сфокусировать окно команд.

`x /[COUNT][FORMAT][SIZE][ADDRESS]`

: Вывести содержимое памяти

  **СOUNT**

  Количество элементов для вывода

  * По умолчанию равен `1`

  * Задается целым числом — `/4`

  **FORMAT**

  Формат вывода данных

  * `s` — строка (набор байтов от заданного до нулевого)

  * `c` — одиночный символ

  * `x` — шестнадцатиричное число

  * `d` — десятичное число со знаком

  * `u` — десятичное число без знака

  * `o` — восьмеричное число

  * `t` — двоичное число

  * `f` — число с плавающей запятой

  * `i` — машинная инструкция

  * `a` — адрес

  **SIZE**

  Размер данных

  * `b` — байт

  * `h` — полуслово

  * `w` — слово (по умолчанию)

  * `g` — гигантское слово

  **ADDRESS**

  Адрес в памяти

# Настройка #
{: id="Настройка" }

`set print elements 0`

: Выводить всё содержимое массива. Не обрезать массив.

`set print repeats 0`

: Не опускать повторяющиеся элементы массива

`set print array on`

: Выводить массив в наглядной форме

`set print array-indexes on`

: Выводить индекс для каждого элемента в массиве

`set print pretty on`

: Выводить структуры в наглядной форме

`set listsize N`

: Выводить N-е количество строк командой `list`

`set confirm off`

: Отключить запрос на подтверждение выполнения команды для всех команд с подтверждением выполнения

# Debuginfod #
{: id="Debuginfod" }

## Что это такое? ##

**Debuginfod** — это клиент-серверная служба (встроенная в современные версии GDB),
предназначенная для динамической загрузки отладочных символов (.debug/DWARF)
и исходного кода прямо из официальных репозиториев дистрибутива Linux.

## Зачем это нужно? ##

1. Избавляет от необходимости вручную искать и устанавливать огромные пакеты
   с отладочными символами (например, `qt5-base-debug`, `glibc-debug`) в ОС.

2. Экономит место в файловой системе: символы скачиваются только для тех библиотек,
   которые реально используются в текущей сессии отладки.

3. Решает проблему ошибок вроде `<incomplete type>` и `No symbol... in current context`.

## Как это работает? ##

1. При сборке системных библиотек дистрибутив вычисляет их уникальный Build ID.

2. Когда GDB загружает вашу программу, он считывает эти Build ID для всех `.so` файлов.

3. Если локальных символов нет, GDB отправляет запрос по HTTP на сервер дистрибутива,
   скачивает нужные дебаг-файлы в локальный кэш (`~/.cache/debuginfod_client/`)
   и „на лету“ подгружает их в отладчик.

## Главные команды управления в GDB ##

`set debuginfod enabled on`

: Автоматически скачивать символы без лишних вопросов (y/n)

`set debuginfod enabled off`

: Полностью отключить службу debuginfod

`show debuginfod enabled`

: Показать текущий статус службы в этой сессии

## Связанные переменные окружения ##

`$DEBUGINFOD_URLS`

: Содержит адреса серверов для загрузки отладочных символов (в Arch Linux: `https://debuginfod.archlinux.org`)

# Примеры #
{: id="Примеры" }

`pipe print /d *buf.constData()@1350 | tee data.txt | bat --color=never --plain`

: * Вывести значение указанного выражения (`print`);

    Вместо `print` можно использовать `p`.

  * Вывести указанное количество байт массива (`ARRAY@LENGTH`);

  * Использовать десятичный формат для выводимого значения (`/d`);

  * Направить текстовый вывод команды GDB на ввод указанной внешней команды (`pipe GDB_COMMAND | LINUX_COMMAND`);

    Вместо слова `pipe` можно использовать `|` (вертикальную черту).

  * Записать вывод GDB в файл и одновременно передать выведенные данные на ввод указанной команде (`tee FILE | COMMAND`);

  * Отобразить вывод GDB (`bat`), отключив окраску текста (`--color=never`) и дополнительные декоративные элементы (`--plain`).

    Вместо `bat` можно просматривать вывод в редакторе Vim. Для чтения из
    `stdin` потребуется передать редактору флаг `-` (дефис) — `command | vim -`.
