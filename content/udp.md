# Глоссарий #
{: id="Глоссарий" }


broadcast

: _широковещательная передача_

  Передача одного сообщения всем узлам сегмента сети

hop

: _транзитный участок_

  Участок между двумя соседними узлами сети.

  _транзитный переход_

  Переход сообщения по транзитному участку (т. е. между двумя соседними узлами сети).

  [Транзитный участок — Википедия](https://ru.wikipedia.org/wiki/Транзитный_участок)

maximum transmission unit, MTU

: _максимальная единица передачи_

  Максимальный размер полезного блока данных, который может быть передан по
  заданному протоколу без фрагментации.

multicast

: _групповая (многоадресная) передача_

unicast

: _одноадресная передача_

time to live, TTL

: _время жизни_

  Максимальное число транзитных переходов, которые может осуществить сообщение
  до его принудительного удаления.

  [Time to live — Википедия](https://ru.wikipedia.org/wiki/Time_to_live)

# Общая информация #
{: id="Общая_информация" }

UDP — простой протокол транспортного уровня ориентированный на передачу датаграмм
заданного размера (то есть, размер задан, он фиксирован, датаграмма имеет начало
и конец).

UDP не имеет механизмов исправления ошибок, контроля последовательности передачи,
устранения дупликатов, управления потоком, устранения перегрузок. UDP не гарантирует,
что данные, вообще, будут доставлены получателю.

UDP предоставляет опциональный механизм обнаружения ошибок посредством
использования проверок контрольных сумм.

UDP сам по себе предоставляет минимальную функциональность, поэтому приложениям,
работающим по этому протоколу предоставляется большая свобода над тем, как
пакеты отправляются и обрабатываются. Если приложению требуется надежность
передачи данных или контроль над последовательностью их передачи, то оно должно
реализовывать все эти проверки самостоятельно.

Назначение UDP — служить средством взаимодействия между процессами, запущенными
на узлах сети.

Межсетевое взаимодействие между самими узлами обеспечивается протоколом IP
(с помощью системы ip-адресов).

UDP определяет метод адресации транспортного уровня посредством использования
нумерованных портов UDP (посредством которых идентифицируются взаимодействующие
между собой процессы). Порт — это некий номер, присвоенный процессу, на узле сети.

Кроме того, UDP включает необязательную возможность обнаружения ошибок посредством
использования контрольных сумм.

Номера портов — это средство идентификации процессов, отправляющих и получающих
данные. Номер порта — это положительное 16-и битное число. Он не соответствует
какой-либо физической сущности на хосте.

Порт отправителя в заголовке датаграммы UDP является необязательным. Он может
быть использован получателем для отправки ответного сообщения. Если этого не
требуется, то номер порта может быть выставлен в 0.

В протоколе IP определен механизм мультиплексирования. Его суть в том, что, если
сообщение приходит на один порт, и на этом порту на хосте работает два процесса
по двум разным протоколам, то процесс-адресат будет определяться по протоколу.
Сам протокол определяется в заголовке датаграммы IP в поле `Protocol`.

Датаграмма UDP состоит из заголовка и тела. Заголовок имеет размер в 4 байта
(или 32 бита) и состоит из 4-х полей: __номер порта отправителя__ (2 байта),
__номер порта получателя__ (2 байта), __длина всей датаграммы__ (2 байта) и
__контрольная сумма__ (2 байта). Тело сообщения несет полезную нагрузку в виде
пакета с данными произвольной длины.

Минимальный размер датаграммы — 8 байт. Это датаграмма, содержащая только
заголовок и не содержащая тела. Если размер датаграммы превышает размер
максимальной единицы транзакции (MTU), то такая датаграмма будет поделена и
передана в нескольких сообщениях IP.

Контрольная сумма, содержащаяся в одноименном поле заголовка датаграммы UDP,
вычисляется на основе заголовка датаграммы UDP, тела датаграммы UDP и псевдозаголовка UDP.

Контрольная сумма вычисляется отправителем и может проверяться получателем
датаграммы UDP.

Контрольная сумма не изменяется в процесс передачи, за исключением случаев,
когда сообщение проходит через NAT.

В протоколе IP определено время жизни передаваемого сообщения. Время жизни
устанавливается в заголовке `Time to live` (или `TTL`) датаграммы IP. Размер этого
заголовка составляет 8 бит (или 1 байт). Обычно значение этого заголовка равно 64.
По мере прохождения транзитных участков это значение уменьшается на 1 за
кажный пройденный участок. Когда значение TTL становится равным 0, сообщение
выбрасывается. TTL создан для того, чтобы препятствовать бесконечному перемещению
сообщения в сетях.
