Глоссарий

acknowledgement, ACK

квитирование; подтверждение (приёма); квитанция

Подтверждение получателем факта приёма сообщения. Слово «квитирование» происходит от «квитанции» — расписки в получении.

См. Квитирование.

acyclic data

ациклические данные

Данные, передаваемые по мере возникновения (события, запросы), а не периодически.

ср. cyclic data

alarm acknowledgement

квитирование аварии (сигнала)

Подтверждение оператором (машинистом) того, что он увидел аварию и принял её к сведению. Регламентируется стандартами ISA-18.2 / IEC 62682.

Не путать с сетевым квитированием (acknowledgement).

automatic repeat request, ARQ

автоматический запрос повторения

Семейство механизмов надёжной доставки сообщений по ненадёжному каналу связи.

См. ARQ.

big-endian

прямой порядок байтов; от старшего к младшему

Старший байт многобайтового числа располагается первым.

ср. little-endian

cumulative acknowledgement

кумулятивное (накопительное) квитирование

Квитанция вида «получены все сообщения до №K включительно». Одна квитанция подтверждает сразу несколько сообщений.

Применяется в TCP и в протоколе IEC 60870-5-104.

cyclic data

циклические данные

Данные, передаваемые периодически, с заданным интервалом, независимо от того, изменились они или нет. Как правило, это состояние процесса (см. process image).

ср. acyclic data

cyclic redundancy check, CRC

циклический избыточный код

Контрольное значение, вычисляемое по содержимому блока данных с помощью полиномиального деления. Служит для обнаружения искажений при передаче.

См. CRC.

data dictionary

словарь данных

Описание того, по какому смещению, какого размера и в каких единицах располагается каждая величина в передаваемом блоке данных.

См. Словарь данных.

deduplication

устранение дубликатов

Распознавание получателем повторно пришедшего сообщения (как правило, по порядковому номеру) и отказ от его повторной обработки.

device announcement

объявление устройства

Специальное сообщение, в котором устройство сообщает о себе сети: кто оно и с какими параметрами работает.

В коде tem18lng — «визитка».

См. Объявление устройства.

discovery

обнаружение (устройств в сети)

Механизм, позволяющий участникам сетевого взаимодействия узнавать друг о друге без ручной настройки адресов.

endianness

порядок байтов

Порядок, в котором байты многобайтового числа располагаются в памяти и в передаваемом сообщении.

См. Порядок байтов.

event

событие

Факт, произошедший в определённый момент времени (например, срабатывание защиты или обрыв датчика).

ср. state

Go-Back-N

возврат на N

Стратегия ARQ с окном из N сообщений: при потере сообщения повторно передаются все сообщения начиная с потерянного.

heartbeat

сердцебиение; сигнал «я жив»

Регулярный сигнал, по наличию которого определяется, что устройство работает и связь с ним есть.

См. Heartbeat.

idempotency

идемпотентность

Свойство операции давать один и тот же результат при однократном и многократном выполнении. Идемпотентная обработка сообщений делает безопасными их повторные доставки.

little-endian

обратный порядок байтов; от младшего к старшему

Младший байт многобайтового числа располагается первым. Такой порядок используется процессорами x86 и, как правило, ARM.

ср. big-endian

liveness counter

счётчик времени жизни (устройства)

Счётчик, который периодически увеличивается по таймеру и обнуляется при каждом сообщении от устройства. При превышении порогового значения устройство считается потерянным.

В коде tem18lng — ttl. Не путать с TTL протокола IP (см. UDP).

piggybacking

попутная передача

Передача служебной информации (событий, квитанций) в составе сообщений, которые и так отправляются.

См. Попутная передача.

plant

объект управления

То, чем управляет система управления: агрегат, установка, технологический процесс.

process

(технологический) процесс

В автоматике — физический процесс, которым управляет система (работа дизель-генератора, газовой системы, тормозов), а не процесс операционной системы.

АСУ ТП — автоматизированная система управления технологическим процессом

process data

данные процесса

Циклически передаваемые по сети данные о состоянии процесса. Термин промышленных сетей PROFINET и EtherCAT.

process image

образ процесса

Область памяти, в которой каждая переменная процесса располагается по фиксированному адресу. Снимок состояния процесса.

Process Image Input, PII — образ входов

Process Image Output, PIO — образ выходов

См. Образ процесса.

process variable, PV

переменная процесса

Измеряемая величина процесса (давление, температура, частота вращения).

retransmission

повторная передача

Повторная отправка сообщения, квитанция на которое не была получена.

scaling

масштабирование

Преобразование «сырого» значения (отсчёта АЦП) в физическую величину и обратно.

См. Масштабирование.

scan cycle

цикл сканирования (ПЛК)

Цикл работы программируемого логического контроллера: чтение входов, выполнение программы, запись выходов.

Selective Repeat

выборочный повтор

Стратегия ARQ с окном, при которой повторно передаются только потерянные сообщения.

sequence number

порядковый номер (сообщения)

Уникальный, как правило возрастающий, идентификатор сообщения. Позволяет указать в квитанции, какое именно сообщение получено, и распознавать дубликаты.

state

состояние

Текущее значение величины или совокупности величин.

ср. event

Stop-and-Wait

остановка и ожидание

Простейшая стратегия ARQ: в пути находится только одно сообщение, следующее отправляется лишь после получения квитанции на предыдущее.

Данные

Технологический процесс

В теории управления и промышленной автоматике процесс — это физический процесс, которым управляет система, — объект управления. Для тепловоза это работа его агрегатов: дизель-генератора, газовой системы, тормозов, тяговых двигателей.

Термин Значение Пример на тепловозе
процесс, объект управления то, чем управляем газовая система тепловоза
переменная процесса измеряемая величина процесса давление газа в баке
вход процесса сигнал от датчика в систему управления показание датчика давления
выход процесса команда системы управления исполнительному устройству открыть отсечной клапан
образ процесса снимок всех входов и выходов в памяти «зеркало»

Слово «процесс» здесь не имеет отношения к процессам операционной системы. Это частый источник путаницы для программистов.

Образ процесса

Образ процесса — непрерывная область памяти, в которой каждая переменная процесса располагается по фиксированному адресу (смещению). Это отражение состояния технологического процесса в памяти.

Термин пришёл из программируемых логических контроллеров (ПЛК, стандарт IEC 61131). ПЛК работает циклами сканирования:

┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ 1. Прочитать все входы          -> записать в образ входов (PII)                         │
│ 2. Выполнить программу          -> работает ТОЛЬКО с образами, а не с «живыми» датчиками │
│ 3. Записать образ выходов (PIO) -> на исполнительные устройства                          │
│ 4. Повторить                                                                             │
└──────────────────────────────────────────────────────────────────────────────────────────┘

Образ процесса обеспечивает согласованность данных: в течение одного цикла программа видит все величины, снятые в один и тот же момент времени.

В сетевом взаимодействии образ процесса передаётся периодически и целиком (циклические данные). Получатель перезаписывает свою копию. Запросов нет. Потеря отдельного сообщения некритична: следующее сообщение принесёт актуальные данные.

Аналоги в промышленных сетях: PDO в CANopen, process data в PROFINET и EtherCAT, карта регистров в Modbus.

«Зеркало» (жаргон tem18lng) — копия образа процесса стойки, циклически передаваемая по сети на дисплейный модуль. Соответствие термину ПЛК не буквальное: «зеркало» передаётся по сети и содержит, помимо входов и выходов, вычисленные значения (например, массу газа) и сообщения. Точнее его назвать данными процесса или циклическими данными.

Словарь данных

Словарь данных — описание структуры образа процесса: по какому смещению, какого размера и в каких единицах располагается каждая величина.

Назначение словаря — быть единым источником истины для всех участников обмена: отправитель упаковывает значения по смещениям, получатель распаковывает их по тому же описанию.

Аналоги: EDS-файлы в CANopen, ESI-файлы (XML) в EtherCAT, DBC-файлы для CAN.

Масштабирование

Величины, как правило, передаются в виде компактных целых чисел («сырых» значений, например отсчётов АЦП), а не чисел с плавающей точкой. Для перевода в физическую величину используется линейное отображение диапазона [rawMin, rawMax] на диапазон [valueMin, valueMax]:

value = valueMin + (raw − rawMin) · (valueMax − valueMin) / (rawMax − rawMin)

Пример: давление газа, raw ∈ [0, 32767], value ∈ [0, 20] МПа. При raw = 16384 значение равно ≈ 10 МПа.

Состояние и событие

Различие между состоянием и событием — ключевое при проектировании протокола. Из него следует выбор механизмов доставки.

  Состояние Событие
Что это текущее значение величины факт, случившийся в момент времени
Пример давление = 10,2 МПа «Обрыв датчика, 14:32:05»
Потеря сообщения некритична событие потеряно навсегда
Механизм доставки периодическая передача (образ процесса) очередь + квитирование + повтор
Вид данных циклические ациклические

Контроль связи

Объявление устройства

Объявление устройства — специальное сообщение, в котором устройство сообщает о себе: кто оно (тип, секция, номер тепловоза), имя и параметры обмена.

Назначение:

  • участники сетевого взаимодействия узнают друг о друге без ручной настройки адресов (discovery);

  • получатель заранее узнаёт метаданные, необходимые для разбора последующих сообщений.

Принцип работы: устройство периодически отправляет объявление. Получатель заносит отправителя в список устройств и помечает его как готового. Данные принимаются только от готовых устройств.

Объявление устройства и циклические данные образуют классическую схему конфигурационное сообщение + циклические данные: редкое сообщение описывает, как читать данные, частое — передаёт что читать.

Аналоги: boot-up message в CANopen, SSDP (UPnP), mDNS/DNS-SD, PROFINET DCP.

«Визитка» (жаргон tem18lng) — объявление устройства. Помимо идентификации устройства, передаёт размер «зеркала», размер его блока и признак главного устройства (isMain).

Heartbeat

Heartbeat — регулярный сигнал «я жив». Если сигнала нет дольше заданного времени, устройство считается потерянным, а связь с ним — отсутствующей.

Роль heartbeat может играть специальное сообщение или любое сообщение от устройства. В tem18lng heartbeat — это любой пакет от устройства, включая «визитку».

Аналоги: heartbeat в CANopen (NMT), keepalive в TCP, BFD.

Счётчик времени жизни устройства

Счётчик времени жизни — способ реализации таймаута heartbeat:

  • по таймеру счётчик увеличивается: ttl++;

  • при каждом сообщении от устройства счётчик обнуляется: ttl = 0;

  • при ttl > ttl_max устройство считается потерянным.

Важно: в коде tem18lng счётчик называется ttl, но по смыслу он не имеет ничего общего с TTL протокола IP (максимальным числом транзитных переходов, см. UDP). Здесь это время, прошедшее с последнего контакта с устройством.

Надёжная доставка

UDP не гарантирует ни доставку, ни порядок, ни отсутствие дубликатов. Для состояния это приемлемо, для событий — нет. Надёжность доставки событий приходится строить на уровне приложения.

Квитирование

Квитирование — подтверждение получателем факта приёма сообщения. Позволяет отправителю узнать, что событие дошло и его можно удалить из очереди.

У термина в промышленной автоматике два значения:

Значение Кто подтверждает Что подтверждает Пример
сетевое квитирование программа, автоматически сообщение доставлено ACK в TCP, IEC 60870-5-104
квитирование аварии оператор, нажатием кнопки авария замечена ISA-18.2 / IEC 62682

Квитанция на квитанцию не нужна: если квитанция потерялась, отправитель повторит сообщение, получатель распознает дубликат и квитирует снова.

ARQ

ARQ (Automatic Repeat reQuest) — семейство механизмов надёжной доставки. Составные части:

  1. порядковый номер сообщения — чтобы квитанция указывала, какое именно сообщение получено;

  2. хранение сообщения у отправителя до получения квитанции;

  3. повторная передача при отсутствии квитанции (как правило, по таймауту);

  4. устранение дубликатов у получателя.

Стратегии ARQ

Стратегия Суть Плюсы Минусы Где встречается
Stop-and-Wait одно сообщение в пути; следующее — после квитанции очень просто одно сообщение за время «туда-обратно» TFTP, простые промышленные протоколы, tem18lng
Go-Back-N окно из N сообщений; при потере повтор всего начиная с потерянного выше пропускная способность лишние повторы HDLC
Selective Repeat окно; повтор только потерянных эффективно у получателя нужен буфер переупорядочивания SCTP, TCP с SACK

Отдельно выделяется кумулятивное квитирование: квитанция «получено всё до №K включительно» (TCP, S-кадры IEC 60870-5-104).

Устранение дубликатов и идемпотентность

Повторные доставки неизбежны: квитанция тоже может потеряться. Поэтому получатель должен распознавать дубликаты по порядковому номеру, не обрабатывать их повторно, но квитировать снова.

Гарантировать доставку «ровно один раз» по ненадёжной сети только средствами транспорта невозможно. На практике используется доставка «хотя бы один раз» (повторы) + идемпотентная обработка (дубликаты отбрасываются). Это рабочий эквивалент доставки «ровно один раз».

Аналог — уровни QoS в MQTT: 0 — «не более одного раза», 1 — «хотя бы один раз», 2 — «ровно один раз».

Попутная передача

Попутная передача (piggybacking) — передача служебной информации в составе сообщений, которые и так отправляются.

Если событие едет внутри циклически передаваемого образа процесса, отдельный таймер повторной передачи не нужен: пока событие не квитировано, оно передаётся в каждом цикле. Повтором служит сам период передачи.

Пример из tem18lng:

  • сообщение стойки передаётся внутри «зеркала»;

  • квитанция дисплейного модуля передаётся внутри его обычного пакета: флаг квитанции, номер квитируемого сообщения и идентификатор адресата (связь широковещательная, поэтому квитанцию слышат все, и каждый проверяет, ему ли она адресована).

Целостность кадра

CRC

CRC (Cyclic Redundancy Check, циклический избыточный код) — контрольное значение, вычисляемое по содержимому кадра. Отправитель вычисляет CRC и записывает его в кадр, получатель вычисляет повторно и сверяет. При несовпадении кадр отбрасывается целиком.

Алгоритм CRC определяется набором параметров:

  • ширина (8, 16, 32 бита);

  • полином;

  • начальное значение;

  • отражение битов на входе и выходе;

  • финальное значение XOR.

Каждый стандартный вариант CRC имеет check value — значение CRC от строки "123456789". По нему проверяется правильность реализации.

Пример: CRC-16/CCITT-FALSE (он же CRC-16/IBM-3740): полином 0x1021, начальное значение 0xFFFF, без отражения, без финального XOR, check value 0x29B1.

Поле CRC принято размещать в конце кадра (Ethernet FCS, Modbus RTU, CAN): контрольная сумма считается по всему кадру, кроме последних байтов, без «магических» смещений.

Прикладной CRC отличается от контрольной суммы UDP (см. UDP): контрольная сумма UDP защищает датаграмму на транспортном уровне и может быть отключена, прикладной CRC защищает смысловое содержимое кадра независимо от транспорта.

Порядок байтов

Порядок байтов многобайтовых чисел в кадре должен быть зафиксирован в спецификации протокола явно. Сериализация «как в памяти хоста» (через memcpy структур) работает лишь до тех пор, пока порядок байтов у всех участников совпадает.

Порядок Число 0x1234 в кадре
little-endian 34 12
big-endian 12 34
